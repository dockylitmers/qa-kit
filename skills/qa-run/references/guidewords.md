# 위험 분석 대입표

## 1. 안내어 (HAZOP → 소프트웨어)

흐름 간선(A → B 호출·메시지·쓰기)마다 모든 안내어를 대입한다. 해당 없음도 "해당 없음: 이유"로 적는다.

| 안내어 | 소프트웨어에서 | 대표 질문 |
|---|---|---|
| 없음 | 웹훅·푸시·예약 작업 미도착, 정리 단계 미실행 | 이 통지가 끝내 안 오면 상태는 어디서 멈추나? 누가 알아채나? |
| 더 많이 | 중복 요청·재전송·몰림·큰 입력 | 같은 통지가 두 번 오면 두 번 처리되나? 멱등 키는 무엇인가? |
| 더 적게 | 일부만 온 데이터, 덜 들어온 입금, 잘린 페이지 | 금액·수량이 기대보다 적으면 검증하나? |
| ~도 함께 | 추가 부수효과(이중 청구, 문자 2회, 이벤트 2번 발행) | 이 처리 중 다른 부수효과가 같이 일어나나? |
| 일부만 | DB는 저장됐는데 외부 호출 미완료, 두 경로 중 한쪽만 정리 | 중간에 끊기면 어느 쪽이 남나? 다시 돌리면 어떻게 되나? |
| 거꾸로 | 상태 역전(완료 → 대기), 환불·청구 부호 반대 | 뒤로 가는 전이를 막는 검사가 있나? |
| 다른 것 | 다른 사용자 객체(권한 우회), 다른 주문에 붙은 영수증 | 식별자를 바꿔 보내면 남의 것이 보이거나 바뀌나? |
| 이르게 | 승인 응답보다 먼저 온 웹훅, 생성 전 도착한 이벤트 | 대상 행이 아직 없을 때 오면? |
| 늦게 | 시간 초과 뒤 늦게 온 성공, 만료 뒤 승인 | 이미 포기·취소한 뒤 성공이 오면 돈과 상태는? |
| 앞서 / 뒤에 | 이벤트 역순 도착, 정리보다 재연결이 먼저 | 순서가 바뀌면 최종 상태가 달라지나? |
| 동시에 | 같은 대상에 두 처리(사용자·배치·관리자)가 겹침 | 잠금·조건부 갱신·유일 제약이 있나? |
| 권한 없음 | 만료 토큰, 다른 역할, 비로그인 | 서버에서 소유권을 다시 확인하나? |

## 2. STPA 위험 제어 동작 4유형

제어 동작 = 상태를 바꾸는 호출(청구, 취소, 발급, 환불, 만료 처리, 재시도, 알림 발송). 동작마다 네 칸을 채운다.

| 유형 | 뜻 | 예 |
|---|---|---|
| 안 함 | 필요한데 실행되지 않음 | 결제 실패 뒤 예약 해제 안 함, 이전 수납 건 정리 안 함 |
| 해서 위험 | 실행했는데 그 상황에서 해롭다 | 이미 환불된 주문에 발급, 취소된 주문에 청구 |
| 때가 틀림 | 너무 이르거나 늦거나 순서가 틀림 | 커밋 전 발송, 승인 전 발급 |
| 너무 일찍 멈춤 / 너무 오래 감 | 지속 시간이 틀림 | 재시도를 너무 빨리 포기, 재시도 폭주, 잠금 미해제 |

## 3. 의존 실패 모드

의존(DB, 캐시, 결제 대행사, 공급사, 메시지, 파일 저장소, 시계)마다 **읽기와 쓰기를 따로** 대입한다.

| 모드 | 확인할 것 |
|---|---|
| 없음(연결 실패) | 예외가 잡히나, 상태는 어디서 멈추나, 사용자에게 무엇이 보이나 |
| 느림(시간 초과) | 시간 초과 값이 있나, 시간 초과인데 실제로는 성공한 경우를 다루나 |
| 오류 응답(4xx/5xx) | 재시도 대상과 비대상을 나누나, 재시도에 멱등 키가 있나 |
| 틀린 값 | 금액·통화·상태 값을 검증하나(외부 값을 그대로 믿지 않나) |
| 중복 | 같은 응답·통지 두 번 |
| 역순 | 오래된 통지가 새 상태를 덮어쓰나 |
| 일부만 | 묶음 중 일부 성공, 페이지 일부 |
| 한도 초과 / 인증 만료 | 429·토큰 만료 시 재시도 폭주나 무한 대기 |

외부 연동 공통 확인: 웹훅 재전송 규칙(응답 시간 한도, 횟수, 간격), 기한 만료 시 통지가 오는지 안 오는지(안 오면 폴링·배치가 필요), 서명 검증, 금액 재확인.

## 4. 대체 경로 비대칭 비교

같은 결과(주문 생성, 결제 확정, 취소, 재발급)를 내는 경로를 모두 적고 표로 맞댄다.

| 단계 | 경로 A | 경로 B | 차이 |
|---|---|---|---|
| 입력 검증 | | | |
| 이전 상태 정리(이전 청구·예약·쿠폰) | | | |
| 잠금·조건부 갱신 | | | |
| 외부 호출과 트랜잭션 경계 | | | |
| 실패 시 보상 | | | |
| 쓰는 테이블·필드 | | | |

한쪽에만 있는 칸이 가설 후보다. 예: "이전 수납 건 정리"가 한 경로에만 있으면, 다른 경로로 들어온 주문에 남은 수납 건이 다시 붙어 두 번 걷힐 수 있다(안내어 '일부만' + '다른 것', STPA '안 함' + '해서 위험').
