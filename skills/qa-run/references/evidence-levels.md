# 증명 등급과 도구 (6단계)

가장 싼 등급으로 확실하게 끝낸다. 깨지는 것이 확실하면 L1에서 멈춘다.

| 등급 | 무엇을 남기나 | 도구(TypeScript 기준, 다른 언어는 대응 도구) | 주의 |
|---|---|---|---|
| L0 코드 근거 | 파일·줄, 호출 경로, 보호 장치가 없다는 근거(잠금·조건부 갱신·멱등 키·검증을 찾아본 위치) | 읽기, grep | "없다"는 주장은 어디를 찾아봤는지 함께 적는다 |
| L1 실패 테스트 | 지금 코드에서 실패하는 최소 테스트 + 실행 명령 + 실패 출력 | 프로젝트 테스트 러너(Jest, Vitest 등) | 기대값은 명세에서. 테스트를 통과시키려고 단언을 약하게 하지 않는다 |
| L2 속성 기반 상태 테스트 | 명령 모델, 깨진 최소 순서, seed | fast-check `fc.commands`, `fc.scheduler`(경쟁·순서) | seed와 경로를 기록해 재실행 가능하게 |
| L3 API 퍼징·교차 접근 | 요청·응답 기록, 두 계정 교차 접근 결과 | Schemathesis(OpenAPI/Swagger), 직접 스크립트 | 버리는 로컬 환경에서만 |
| L4 장애 주입 | 실험 계획(가설·중단 조건·되돌리기) + 결과 | Toxiproxy(DB·캐시·외부 API 앞 지연·끊김), WireMock·MSW(지연·빈 응답·깨진 응답), Playwright `route.abort`·`setOffline`·`clock`, 프로세스 종료 | 계획을 먼저 쓴다. 공유 환경은 승인 필요 |
| LD 기기 재현 | 기기·OS·빌드, owner, 명령과 출력, 단계별 캡처·녹화, 재현 횟수, 바꾼 기기 설정과 복구 확인 | device-qa(시뮬레이터·에뮬레이터), 실기기는 Appium 직접 | 증거는 `evidence/<가설>/device/`. 재현 못 하면 L0로 남긴다 |
| L5 변이 테스트 | 살아남은 변이 목록 | Stryker(결제·상태 모듈로 좁혀서) | 시간이 많이 든다. 테스트 공백을 보일 때만 |

## 버리는 사본

```sh
mkdir -p "$RUN/sandbox"
git -C "$REPO" archive HEAD | tar -x -C "$RUN/sandbox"
# 의존이 필요하면 사본 안에서 설치하거나 레포의 node_modules를 링크
ln -s "$REPO/node_modules" "$RUN/sandbox/node_modules"   # 모노레포면 패키지별로
```

레포 자체에는 파일을 만들지 않는다(테스트 파일·설정·캐시 포함). 실행 결과의 캐시·빌드 산출물이 레포 안에 생기는 명령(레포 경로에서 `npm test` 등)은 쓰지 않는다.

## 증거 묶음

`evidence/<가설 번호>/`:
- `README.md` — 가설 문장, 등급, 실행 명령, 기대(명세 근거)·실제, 결론
- 테스트 파일, 출력 로그(실패 확인 부분), seed, 실험 계획
- 비밀값·실고객 데이터 없음
