# 장애 설계 카드 (2단계)

기능 하나에 카드 하나. 모든 칸에 파일·줄을 붙인다. 모르는 칸은 "미확인"으로 남긴다.

```markdown
## <기능 이름>

### 흐름
<진입점> → <처리> → [경계: 외부 API / 웹훅 / 큐 / 트랜잭션] → <처리> → <출구>
- 경계마다: 시간 초과 · 재시도 · 멱등 키 · 트랜잭션 안/밖  (파일:줄)

### 상태 기계
| 상태 | 다음 상태 | 전이 주체(사용자·웹훅·배치·관리자) | 검사(조건부 갱신·잠금) | 파일:줄 |
- 무효 전이(일어나면 안 되는 것): 완료 → 대기, 환불 → 발급 …  막는 코드가 있나?

### 불변식 (증명의 판정 기준)
- I1: 주문당 성공 청구 ≤ 1
- I2: 발급은 결제당 1회
- I3: 환불 합계 ≤ 결제액
- I4: 권한 밖 데이터는 읽기·쓰기 불가
- 근거: 명세 위치 (코드가 아니라 명세·수용 기준에서)

### 데이터 쓰기 지도
| 경로(진입점) | 테이블·필드 | 쓰기 종류(생성·갱신·삭제) | 트랜잭션 | 파일:줄 |
- 같은 테이블을 바꾸는 경로가 둘 이상이면 3단계 비대칭 비교 대상

### 되돌릴 수 없는 출구
| 출구(청구·환불·발급·발송) | 앞선 검사 | 커밋 전/후 | 멱등 | 파일:줄 |

### 명세가 다룬 것 / 다루지 않은 교차 지점
- 다룸: … (구현과 대조)
- 교차 지점 가설: <기능 X> × <실패 Y>
```
